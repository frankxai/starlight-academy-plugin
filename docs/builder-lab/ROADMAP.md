# Builder lab implementation and release packet

Date: 2026-10-01. Owner: Starlight Academy plugin. Scope: a reusable builder lab
and external-distribution blueprints. This is an implementation packet; it grants
no cross-repository dispatch, new service, payment or publishing authority.

## Current artifact

`plugins/starlight-builder-lab` contains three skills, offline source generation,
package checking and reproducible ZIP creation. The external kit under
`docs/builder-lab` contains the commerce skill, economics calculator, channel
requirement drafts and commercial blueprints. Commerce guidance is excluded
from the directory-candidate ZIP. It deliberately uses no MCP server because these
operations work through the customer's host and filesystem.

The paid-value hypothesis is maintained, tested workflows for a particular buyer
task. Generic scaffolding already exists free. Research references include the
OpenAI creator/packaging guide, Claude marketplace tooling and native Polar
delivery. The lab adds a complete inspectable example, preservation checks,
negative cases, separate release statuses and explicit cost modeling. Comparative
host outcomes and willingness to pay remain unmeasured.

## Sequenced acceptance

1. **Local source proof:** run deterministic tests; inspect example round trip,
   source manifest, relative references, ZIP entries and secret-scan evidence.
2. **Workflow proof:** execute success, missing evidence, malicious source and
   transfer tasks in Codex and Claude. Record assistance and baseline comparison.
3. **Dots proof:** verify account eligibility, installed plugin support and local
   computer permission. Exercise one bounded research responsibility. Record
   cloud/local task identity and denied-action behavior. No speculative pass.
4. **Independent review:** a separate provider checks craft, source, current
   policy interpretation and negative cases. Fix findings before catalog inclusion.
5. **Free distribution:** add version-pinned Codex/Claude catalog entries after
   host checks. OpenAI directory submission is a separate verified-identity step.
   Preserve skills-only identity; use a separate package for a later MCP integration.
6. **Paid workflow:** capture role, reason and buyer-chosen price band through the
   existing demand system. Complete an original domain pack and its comparison
   tests. Do not treat the free lab's license as an exclusive paid entitlement.
7. **Commerce proof:** confirm the actual external account's plan; test managed
   download/access benefits, refunds and update periods in sandbox. Recalculate
   contribution with measured fees/costs. Enable checkout only after the product
   release gate passes.

## Observable measures

Track task success, unsupported claims, trigger precision, correction time,
first-run completion, user assistance, total provider cost and maintenance
burden. Commercial measures are demand-qualified requests, price evidence,
conversion, net receipts excluding tax/refunds, return rate and contribution.
Record counts from events; no seeded scarcity or earnings estimates.

## Current limitations

No paid product, live storefront, new scheduler or global runtime configuration
is created here. No host compatibility or Dots-access claim follows from file
checks. Marketplace inclusion, provider approval, demand and price evidence are
separate unfinished gates. The existing Academy release receipts describe the
previous packages; they are not certification for this new candidate. The commercial `plan` command lists required evidence; it does
not evaluate or enforce the release gate.

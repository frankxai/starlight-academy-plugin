# AI Department Verification Matrix

| Gate | Evidence | Pass condition | Severity if absent |
|---|---|---|---|
| Intelligence objective | prompt, outcome target, measurement state, governing constraints | seeks maximum useful reasoning without trading away truth, authority, privacy, safety, or reversibility | critical |
| Workflow fit | preserved triage and real sample cases | bounded workflow or explicit assist/do-not-automate decision | critical |
| Human authority | permission map and exact approval fixtures | no self-sponsorship, blanket approval, or authority expansion | critical |
| Data boundary | approved source/system inventory and secret scan | no undeclared private data, credentials, or memory | critical |
| Separation | role graph and evaluator provenance | producer is not final verifier | critical |
| Simplicity | topology decision record and comparative evidence | each agent/tool has a necessary independent responsibility | high |
| Evidence | source/tool lineage and exception record | material claims and completion state are inspectable | high |
| Evaluations | pinned tasks, graders, thresholds, transcripts, failures | representative success plus critical criterion floors | high |
| Adversarial safety | injection, authority-bypass, false-completion tests | failures stop, escalate, and remain visible | critical |
| Recovery | revocation, rollback, partial-failure test | safe stop and return to human operation work | critical |
| Package security | manifest, script, MCP, dependency, and network inspection | capabilities match declarations; no hidden side effect | critical |
| Portability | official-source runtime matrix with checked dates | native/compatible/adapter/unverified states are distinct | medium |
| Claims | public copy and marketplace metadata | no false live, approval, outcome, accreditation, or autonomy claim | critical |

## Verification record

For every check, capture:

- component and exact version or digest;
- verifier identity and independence status;
- command, fixture, or inspection method;
- observed result and retained evidence;
- verdict, severity, owner, remediation, and retest;
- tests not run and the claims therefore blocked.

A changed mission, skill, model, tool, permission, system prompt, policy, or
runtime invalidates only the evidence it materially affects, but that scope must
be justified rather than assumed.
